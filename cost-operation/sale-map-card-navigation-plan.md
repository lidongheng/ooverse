# 地图卡片联动 ECS 详情与大区筛选

## 目标

在 `/#/saleHome` 页面点击地图中的任意大区卡片后：

- 跳转到 `/#/saleDetail?type=ECS`；
- 左上角筛选只选中当前卡片对应的大区；
- 同时选中该大区所属的区域，以及该大区下的全部 Region；
- 清空原先选择的其他区域、大区和 Region。

## 实施方案

### 1. 增加大区筛选方法

在销售筛选 Pinia store 中增加按大区名称选择的方法：

- 等待区域树加载完成，避免初始化的默认全选覆盖地图点击产生的选择；
- 使用地图卡片传入的大区名称，在“区域 → 大区 → Region”三级树中进行精确匹配；
- 匹配成功后，将筛选值更新为：
  - 当前大区所属的顶层区域；
  - 当前大区；
  - 当前大区下的全部 Region；
- 不保留其他区域、大区或 Region 的原有选择；
- 不添加默认值、别名映射或名称转换等兜底逻辑。

### 2. 增加地图卡片跳转逻辑

在地图 composable 中封装卡片点击方法：

- 接收卡片实际的大区名称；
- 调用筛选 store 的大区选择方法；
- 跳转到 `/saleDetail?type=ECS`；
- 路由中不增加大区名称等额外 query 参数。

### 3. 绑定地图卡片点击事件

给地图中整个 ECharts `graphic.group` 卡片增加点击事件：

- 点击卡片任意位置均触发 ECS 详情跳转；
- 使用卡片数据中的实际大区名称，不写死“西部”等具体值；
- 保留现有卡片拖拽功能；
- 拖动卡片时不能误触详情跳转。

### 4. 保持现有筛选组件不变

- 不修改通用的 `FilterDropdowns.vue`；
- 继续通过现有 Pinia store 和 `v-model` 同步左上角筛选展示；
- 不修改本地筛选树 Mock 数据；
- 真实区域树存在与卡片同名的大区时完成筛选联动；
- 找不到精确同名节点时，不构造任何兜底筛选值，但仍跳转 ECS 详情。

## 接口变化

- 销售筛选 store 新增异步 action：接收大区名称，完成区域树精确匹配和三级筛选值更新；
- 地图 composable 新增卡片点击方法：接收大区名称，更新筛选并跳转 ECS 详情；
- 路由地址保持为 `/saleDetail?type=ECS`。

## 验收场景

1. 使用真实接口数据点击“西部”卡片：
   - 地址变为 `/#/saleDetail?type=ECS`；
   - 详情左侧激活 ECS；
   - 左上角只选中西部所属区域、西部及西部下全部 Region；
   - ECS 详情请求使用更新后的 `areaName` 和 `regionName`。
2. 先手动选择其他大区，再点击西部，确认原有选择被清空。
3. 在区域树仍在加载时点击卡片，确认加载完成后选择不会被默认全选覆盖。
4. 拖动地图卡片，确认仍可调整位置且不会跳转。
5. 点击区域树中不存在同名节点的卡片，确认不生成兜底筛选值，但仍跳转 ECS 详情。
6. 使用 pnpm 9.15.9 执行生产构建，并运行 `git diff --check`。

## 实施约束

- 遵循最小修改原则；
- 不修改与该功能无关的已有代码；
- 不覆盖工作区当前未提交改动；
- 不添加兜底值；
- 不使用嵌套三元表达式；
- 新增代码优先使用单引号，每个语句末尾添加分号；
- 只在必要的代码逻辑中添加注释；
- Vue 文件只消费 composable 暴露的方法和响应式数据，与 Mock 数据交互的逻辑保留在 composable 中。

## 前提

- 地图卡片的大区名与真实区域树中的大区名完全一致；
- “所有子项”指该大区下的全部直属 Region，并同时选中其所属顶层区域；
- 当前示例以地图现有的“西部”为准，不添加“西部 → 西南”等映射。
